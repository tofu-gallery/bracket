# Tofu gallery copy

This repository is Tofu's copy of **evroon/bracket** (licence: AGPL-3.0), listed in Tofu's app gallery as **Tournament planner**: Bracket, a tournament system. Clubs run tournaments with teams, players and courts; stages are round-robin groups, single elimination or Swiss rounds; Bracket schedules the matches, keeps the scores and rankings, and can publish a public dashboard of the schedule and standings for each tournament.

- `master` mirrors the upstream repository and is never committed to by Tofu.
- `tofu` carries Tofu's own changes; tags named `pin/<date>` mark the versions the gallery points to. The current pin is `pin/2026-10-26.1`. It replaces `pin/2026-10-26` for new copies: a copy's first deployment of that version answered with a warning from Tofu's safety check that sign-in would break once the app is live, because a redirect pointed to `localhost`; it came from upstream's commented-out Google sign-in code, which never ran. Tofu's upload of a folder or a ZIP also does not take that version's `frontend/.env.development` (see "What Tofu changes"). Nothing the image runs changes apart from its source link. `pin/2026-10-26` itself replaced `pin/2026-10-25.1`: when Tofu started several copies of that version at once on a new copy's empty database, all but one could stop with a duplicate-object error, and Tofu could refuse the first deployment; its tables were also open to the database's public Data API (see "Start-up when several starts run at once"). `pin/2026-10-25.1` replaced `pin/2026-10-25`, whose image ran its server as a user that cannot bind port 80 (see "How Tofu runs it").
- A visitor who chooses this app gets a private snapshot of the pinned version in their own Tofu account. Their copy does not follow upstream updates.
- Upstream: https://github.com/evroon/bracket at `37e7db76e2d54d89cf2e4333fb03699de341b6a6` (2026-10-26), merged into `tofu` on 2026-10-26. Since `97f408a488a0b1bed7cf7cd53f6394aea8eb9d67` (2026-10-20), the upstream version of the earlier pins, upstream changed only the dependencies of its documentation website (`docs/package.json` and `docs/pnpm-lock.yaml`: Next.js 16.3.8 to 16.4.1, DOMPurify 3.4.16 to 3.4.17), which the image does not include.

## How Tofu runs it

- Framework preset `container`, root folder: the repository root. Tofu builds the root `Dockerfile` and runs the image as a service, so there is no separate install command, build command or output directory.
- The `Dockerfile` is upstream's two-stage build. The frontend (React and Vite) is built with Node 26 and the pnpm package of Alpine Linux: `CI=true pnpm install`, then `VITE_API_BASE_URL=/api pnpm build`. The backend (FastAPI on Python 3.14) is installed with `uv sync --no-dev --locked`. One container serves both: the API under `/api` and the built frontend at every other address. It runs `gunicorn` with one Uvicorn worker on `PORT`.
- The build steps run as the user `bracket`, as upstream has them; the server runs as root (`USER root` right before `CMD`). Tofu's container hosting sets `PORT=80` unless the app has a `PORT` setting, and a process that is not root cannot bind a port below 1024. HomeBox, the container copy already verified on Tofu, runs as root the same way.
- Database: PostgreSQL, the app's Tofu database, read from `DATABASE_URL`. Bracket keeps all its data there; nothing else is kept between restarts (see "What works differently on Tofu").
- The schema: the app makes it itself at start, in one transaction under one lock (see "Start-up when several starts run at once"): on an empty database its tables (SQLAlchemy's `create_all`, then `alembic stamp head`); at every start `alembic upgrade head`, which does nothing while the database is current, and its table `tofu_logos`; and last, row-level security on every table, so that the database's public Data API reads and writes none of them. There are no `supabase/migrations` files, so Tofu applies no SQL of its own.
- Settings Tofu sets: `PORT` and `DATABASE_URL` (and `SUPABASE_URL`, `SUPABASE_ANON_KEY` and `SUPABASE_CA_CERT`, which Bracket does not read).
- Settings the image sets: `ENVIRONMENT=PRODUCTION`, `SERVE_FRONTEND=true`, `API_PREFIX=/api`, `ALLOW_DEMO_USER_REGISTRATION=false` and `SOURCE_URL` (this repository at the pin's tag). A setting of the same name on the app's Keys & settings page wins over the image's.
- Settings filled in at start when `DATABASE_URL` is set and they are not: `PG_DSN` (from `DATABASE_URL`, in session mode) and `JWT_SECRET` (derived from `DATABASE_URL`). See "What Tofu changes" and "The sign-in secret".
- Nothing has to be set by hand before the first deploy. Settings an owner may add:
  - `ALLOW_USER_REGISTRATION=false` closes sign-up (see "Accounts").
  - `SOURCE_URL`, the address of the copy's source code (see "Licence and source code").
  - `JWT_SECRET`, a sign-in secret of the owner's own, as a hidden value (see "The sign-in secret").
  - `ADMIN_EMAIL` and `ADMIN_PASSWORD`, as hidden values, only before the first deploy: on an empty database Bracket then creates an account with them. Bracket has no admin role; the account is an ordinary one.
  - `PG_POOL_MIN_SIZE` and `PG_POOL_MAX_SIZE` (1 and 5), the database pool.
  - `CORS_ORIGINS`, `SENTRY_DSN` (error reports to the owner's own Sentry project; none are sent without it), `PG_DSN` (a connection string of the owner's own, used as it is).

## What Tofu changes

- `Dockerfile`:
  - The frontend is built with `VITE_API_BASE_URL=/api`, so it calls the API on its own address. Upstream builds it for `http://localhost:8400/api`, which only works in a browser on the machine running the container.
  - `ENVIRONMENT=PRODUCTION`, `SERVE_FRONTEND=true` and `API_PREFIX=/api` are image defaults. Without `ENVIRONMENT`, Bracket starts in development mode, which has a fixed admin email and password and a fixed JWT secret in its code (`backend/bracket/config.py`, `DevelopmentConfig`) and creates that admin account on an empty database. Upstream's `docker-compose.yml` sets the other two.
  - `ALLOW_DEMO_USER_REGISTRATION=false`: no demo accounts (see "What works differently on Tofu").
  - `SOURCE_URL=https://github.com/tofu-gallery/bracket/tree/pin/2026-10-26.1` is an image default (see "Licence and source code").
  - The command runs through `/bin/sh -c` and binds `0.0.0.0:${PORT:-8400}`: Tofu sends traffic to `PORT`, and upstream listens on 8400. The `HEALTHCHECK` asks `/api/ping` on the same port.
  - `USER root` right before `CMD`: upstream's image runs the server as the user `bracket`, which cannot bind port 80, the `PORT` Tofu's container hosting sets. The image still installs the backend as `bracket`.
- `backend/bracket/config.py`:
  - When `DATABASE_URL` is set and `PG_DSN` is not, `PG_DSN` is `DATABASE_URL` with the scheme `postgresql`, and with port 6543 changed to 5432 when the host's name contains `.pooler.`. Any other address is kept as it is. Tofu's `DATABASE_URL` names a Supavisor pooler in transaction mode (6543): Supabase Cloud's (`aws-0-<region>.pooler.supabase.com`) or Tofu's own database backend's (`aws-0-<region>.pooler.<domain>`), which an account can be moved onto; nothing here depends on which. Bracket queries PostgreSQL through asyncpg (with the `databases` library), which prepares each statement and runs it in a second round trip, outside any transaction; a transaction pooler may send that second round trip to another server connection, where the statement does not exist. The same pooler serves session mode on 5432, with the same user, password and database, and keeps one server connection for each client connection.
  - Neither connection depends on the pooler's certificate: the `databases` library passes asyncpg no `sslmode` (only an `ssl` option from the URL), so asyncpg uses its default, `prefer`, which is TLS when the server offers it, without checking the certificate; psycopg2 (the start's schema step: the lock, `create_all` and Alembic) reads `sslmode=require`, which checks no certificate either while the image has no `~/.postgresql/root.crt`.
  - When `DATABASE_URL` is set and `JWT_SECRET` is not, `JWT_SECRET` is the SHA-256 of `bracket-jwt-secret:` followed by the whole `DATABASE_URL`, as 64 hex characters. Bracket refuses to start in production without a JWT secret, and Tofu does not supply one.
  - New settings `PG_POOL_MIN_SIZE` (1), `PG_POOL_MAX_SIZE` (5) and `SOURCE_URL` (default: this repository).
- `backend/bracket/database.py`: the connection pool holds `PG_POOL_MIN_SIZE` to `PG_POOL_MAX_SIZE` connections. asyncpg's default opens 10 at start and keeps them; in session mode the pooler admits only as many clients as its pool holds, and a deploy briefly runs the old and the new container side by side. The SQLAlchemy engine, whose one connection does the start's schema step, has no pool (`NullPool`), so that connection closes as soon as the step commits; with upstream's default pool it stayed open until the process ended, a sixth connection beside the asyncpg pool's five. At start, Alembic's commands run on that same connection; run on their own (from the command line), Alembic's engine has no pool either (upstream's `backend/alembic/env.py`).
- `backend/bracket/utils/db_init.py`: an empty database gets its tables without `ADMIN_EMAIL` and `ADMIN_PASSWORD` too. Upstream creates the tables only when both are set; without them, the start goes on to the migrations, whose first one (`274385f2a757`) expects the tables and fails (`index "ix_users_email" does not exist`), and the app does not start. The start now makes this test inside its schema step (`backend/bracket/utils/tofu_schema.py`, below), with the same rule; `init_db_when_empty` itself is kept for upstream's `create-dev-db` command.
- Logos (`backend/bracket/utils/tofu_logos.py`, Tofu's own file; `backend/bracket/routes/tournaments.py`, `backend/bracket/routes/teams.py`, `backend/bracket/app.py`): Bracket saves an uploaded team or tournament logo as a file under `static/`, which Tofu's hosting loses at every restart and deploy. The upload routes now also save the logo in the table `tofu_logos` (folder, file name, bytes), and `GET /api/static/team-logos/<file>` and `GET /api/static/tournament-logos/<file>` answer from the file when this server has it, else from the table, with `Cache-Control: public, max-age=86400`. A name that is not `<uuid>.png|jpg|jpeg` answers 404. A logo's row is deleted as soon as nothing names it: right after a team's or tournament's logo is replaced or removed, and right after a team or tournament is deleted. At every start, a row that no team or tournament names and that is older than an hour is deleted too, for anything those missed (a server stopped between saving a new logo and naming it). The upload routes refuse a file over 5 MB with 413 before they write or save anything; upstream checks the size only in the browser (the upload box in `frontend/src/components/utils/file_upload.tsx`), so a file posted straight to the API could be any size.
- `backend/bracket/app.py`: the job that deletes expired demo accounts every five minutes starts only while demo accounts can be made; the image turns them off. The API documentation's links name this copy's source (`SOURCE_URL`) and the upstream project. At start, the app runs Tofu's schema step (`prepare_schema()`) in place of upstream's `init_db_when_empty()` and `alembic_run_migrations()` and the logo table's own step.
- The start's schema step (`backend/bracket/utils/tofu_schema.py`, Tofu's own file; `backend/bracket/utils/alembic.py` and `backend/alembic/env.py`, so that Alembic's commands can run on a connection the caller gives, inside its transaction; `create_logo_table` in `backend/bracket/utils/tofu_logos.py`, now on that connection): see "Start-up when several starts run at once".
- A source link for AGPL-3.0 section 13:
  - `backend/bracket/routes/internals.py`: `GET /api/source` redirects (302) to `SOURCE_URL`.
  - `frontend/src/services/adapter.tsx` adds `getSourceCodeUrl()`, which is `/api/source` on this image.
  - `frontend/src/pages/login.tsx`: the sign-in page shows a "Source code" link under "Create Account - Forgot password?", before anyone signs in.
  - `frontend/src/components/navbar/_main_links.tsx` (the signed-in "More" menu's "GitHub") and `frontend/src/components/dashboard/footer.tsx` (the public dashboard's footer, "GitHub") open `/api/source` instead of upstream's repository.
- `frontend/src/main.tsx`: upstream's `AnalyticsScript` is removed. It added a third-party analytics script to every page when `VITE_ANALYTICS_SCRIPT_SRC` (with `VITE_ANALYTICS_DATA_DOMAIN` and `VITE_ANALYTICS_DATA_WEBSITE_ID`) was set when the frontend was built. This image never set it, since its build passes no such value, but a copy loads no analytics at all now.
- `backend/bracket/routes/auth.py` (`pin/2026-10-26.1`): upstream's commented-out Google sign-in code is deleted, a `GoogleSSO` client with its helpers and the `/login` and `/sso_callback` routes; none of it ran. Tofu's safety check reads comments too, and a copy's first deployment of `pin/2026-10-26` answered with its warning that sign-in would break once the app is live, because a redirect in that code (line 41) pointed to `localhost`. Only those comment lines and the blank lines that belonged to them are deleted; the imports and every line that runs stay as upstream has them.
- `frontend/.env.development` (`pin/2026-10-26.1`) is deleted. Tofu's upload of a folder or a ZIP does not take files named `.env.*` (apart from `.env.example`, `.env.sample` and `.env.template`), although the gallery's import from GitHub keeps them, so a copy uploaded that way could not keep it. ## Start-up when several starts run at once

Tofu's container hosting can start the app several times within a second or two when a new deployment gets its first requests: the live check of 2026-10-26 saw 4 to 10 starts in one deployment, each a separate container against the same database. On a new copy's empty database, `pin/2026-10-25.1` let every start find the database empty and create the tables at the same moment; all but one stopped with `psycopg2.errors.UniqueViolation ... pg_type_typname_nsp_index ... (tournament_status, 2200) already exists`, answered 500, and Tofu refused the first deployment 1 time in 3.

- **Where the lock is.** `backend/bracket/utils/tofu_schema.py`, `prepare_schema()`, which the app's lifespan (`backend/bracket/app.py`) runs before the server answers any request. It opens one connection from the SQLAlchemy engine (psycopg2, to `PG_DSN`: `DATABASE_URL` in the pooler's session mode, port 5432) and does the whole schema step in ONE transaction on it. The transaction's first statements are `SET LOCAL lock_timeout = '180s'` and `SELECT pg_advisory_xact_lock(7093850510958225517)`; the key is the ASCII bytes of `brktschm`, the same in every start of this app.
- **Why it holds through Tofu's pooler.** A transaction-level advisory lock belongs to the transaction that took it. A pooler in transaction mode keeps a transaction on one server connection from its first statement to its commit, and in session mode (which this app uses) the whole client connection stays on one server connection; either way the lock is held for exactly as long as the transaction that does the work, and the commit or rollback releases it, also when a start dies (the server ends the transaction when its connection drops). A session-level lock (`pg_advisory_lock`) taken through a transaction pooler would not be reliable; this one does not depend on the pooler's mode.
- **What the step does.** Inside the lock, the start looks at the database again (upstream's test: at most one table in `public`) and never assumes it is still empty. The first start creates the tables with `create_all`, stamps Alembic's latest revision and, when `ADMIN_EMAIL` and `ADMIN_PASSWORD` are both set, creates that account; then every start runs `alembic upgrade head`, creates `tofu_logos` if it is missing, and turns row-level security on. PostgreSQL's DDL is transactional, so a start that stops half-way leaves nothing behind, not even Alembic's stamp without the tables.
- **The other starts** wait at the lock for at most 180 seconds (`lock_timeout`; past that, the start stops with an error and the hosting starts it again). Each then finds the work done: `alembic upgrade head` finds the database at the head, `tofu_logos` is there, and every table already has row-level security, so it alters nothing and takes no table lock. A start that still meets a duplicate-object error (`42P07`, `42710`, `42P06`, `23505`) or a deadlock (`40P01`), for example from a process that does not take the lock, rolls back and does the whole step once more.
- **Row-level security** covers every ordinary table in `public` that the app's role owns: Bracket's 14 (`clubs`, `courts`, `matches`, `players`, `players_x_teams`, `rankings`, `rounds`, `stage_item_inputs`, `stage_items`, `stages`, `teams`, `tournaments`, `users`, `users_x_clubs`), Alembic's `alembic_version` and Tofu's `tofu_logos`: 16 tables. It is one `DO` block, the step's last statement. No policy is added, so the Data API's roles `anon` and `authenticated` see no row of any of them and can write none, although today's Tofu databases grant them every new table in `public`. Bracket's own connection owns the tables, so row-level security does not limit it. The step never turns row-level security off and leaves a table another role owns alone.
- **A first start is quick.** On an empty database the first start sends 95 statements (counted with `log_statement = 'all'`), all on one connection apart from the asyncpg pool's, against 116 for `pin/2026-10-25.1`, which opened a new connection for `create_all` and for each Alembic command. Through a proxy that holds every packet 10 ms each way (a 22 ms round trip, like Tofu's pooler), it answered its first 200 3.25 seconds after the process started; its transaction took 1.9 seconds. A later start, on a ready database, sends 22.
- **The five-starts test** (see "Verification") starts five copies at the same instant on an empty database. On `pin/2026-10-25.1` four of the five stopped with that `UniqueViolation` and all 16 tables were open to `anon`; on `pin/2026-10-26` all five answered 200, one start created the tables, no log had an error, and `anon` read and wrote nothing, in three runs through the proxy and three without it, and on this pin the same in three runs without it.

## The sign-in secret

Bracket signs each sign-in token with `JWT_SECRET`; a token is valid for a week.

- On Tofu the secret is derived from `DATABASE_URL` each time the container starts (above), so nothing has to be set.
- Anything that changes `DATABASE_URL` changes the secret at the next start: a new database password, a different host, port or pooler address, other query options, or a database Tofu brings back or creates anew under a different address. After that start, every token issued before is refused, so everyone is signed out once and signs in again with the same email and password. Accounts, tournaments and everything else in the database are not affected.
- To keep sign-ins independent of the database address, set `JWT_SECRET` as a hidden value on the app's Keys & settings page, for example the output of `openssl rand -hex 32`, and keep it unchanged afterwards. Moving from the derived secret to your own also signs everyone out once.
- The derived secret is only as secret as `DATABASE_URL`, which Tofu keeps as a hidden value.

## What works differently on Tofu

- **Accounts.** Bracket has its own email and password accounts, not Tofu sign-in. Anyone who can open the address can create an account on its sign-up page ("Create Account") until the owner sets `ALLOW_USER_REGISTRATION=false` after creating their own account, or makes the app private on Tofu. Closing sign-up does not affect accounts that exist. No account is special: each account sees the clubs it created or was added to, and the first account is not an admin. There is no email: "Forgot password?" opens a page upstream has not built yet ("not found"), so a forgotten password cannot be reset from the app.
- **No analytics, no captcha.** The copy loads no analytics script (above). hCaptcha stays off: the sign-up and demo pages show it only when `VITE_HCAPTCHA_SITE_KEY` is set when the frontend is built, and the image's build sets only `VITE_API_BASE_URL` (the `Dockerfile` declares no build argument, so no setting reaches the build). The server checks a captcha only when `CAPTCHA_SECRET` is set; leave it unset, because without a site key in the frontend every sign-up would then be refused.
- **No demo accounts.** Upstream's demo sign-up (`/demo`) makes throwaway accounts that a job deletes after a while; here it answers "Demo account creation is unavailable for now". An owner can turn it back on with `ALLOW_DEMO_USER_REGISTRATION=true`, which also starts that job.
- **Logos are kept in the database** (above), up to 5 MB each, and only while a team or tournament names them. They are the only files Bracket writes; everything else it stores goes straight into the database.
- **The database connection uses the pooler's session mode** (above). Each container holds at most five connections of the pooler's pool: the asyncpg pool's, which opens one at start and grows with traffic. At start, the schema step opens one more connection for its transaction and closes it.
- **The database's public Data API sees none of Bracket's tables.** Row-level security is on for all of them with no policy (see "Start-up when several starts run at once"); everything goes through Bracket's own API.
- **The "API docs" link in the "More" menu opens a "not found" page.** It points to `/api/docs`, which the frontend answers, while the API's documentation is served at `/docs` (Swagger UI) and `/redoc`. Upstream's own single-container setup (`docker-compose.yml`) behaves the same; this copy leaves it alone.
- **Times.** Bracket reads timestamps from the database assuming the connection's time zone is UTC, which is the Supabase default. A database set to another time zone would shift the times shown.
- **`/api/metrics`** is public, as upstream has it: request counts and response times per endpoint, nothing about accounts or tournaments.
